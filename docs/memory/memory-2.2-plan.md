# 记忆系统 2.2.0 优化与复测方案

日期：2026-10-22。本方案在本轮生产代码修改与评测前固定。基线为2.1.0冻结代码及160题结果。

## 改动范围

1. 多证据检索：减少泛词、同源重复和长助手回复对排序的干扰；扩充有界候选，按问题关键词覆盖与来源多样性选择证据。保留单次6500字符预算，最多12条短证据；自动检索和最多两次模型回忆的调用预算不增加。补充同主题可见历史，使当前值与之前的值能一起被检查。
2. 时间与状态：向提取器提供与新事件相关的已有主题，而非仅最新12条；明确区分累计值、增量、目标/建议与已发生事实。修复乱序写入与明确更新的版本链处理，不以最新时间无条件覆盖矛盾。
3. 证据检查：提示模型按所问字段核对人物、数值、单位、日期、比较方向及信息是否齐全；只用可见证据支持答案，缺项先检索，仍不足则说明缺失。该项是生产读取提示约束，不宣称确定性事实验证器。
4. 保持敏感过滤、成员与会话隔离、引文共享边界和删除语义。普通成员发言不伪装成机器人共同经历。不引入原始聊天全库搜索或外部向量服务。

设计决策：No design pattern: plain implementation is simpler. 使用小型检索辅助函数与现有版本写入机制。

## 冻结评测

- 原126题与上一轮34题留出均已查看过，本轮合称160题回归集，分别报告原分层以便纵向比较，不再称上一轮34题为盲测。
- 新增34题：LME按原7层各抽2题（14）；LoCoMo按5类各抽4题（20），尽量分散到不同对话。固定种子20261024，排除前160题，在本轮实现前保存清单。LoCoMo仍使用相同10个对话，仅是新问题留出，不是新对话泛化测试。
- 新版194题均从完整历史写入干净库，执行none/oracle/memory三条件，共582份结果；旧2.1.0冻结实现独立运行新增34题三条件，共102份控制。历史160题对照不是同期重跑。
- 模型继续deepseek-flash，temperature=0，thinking关闭；评分脚本、数据哈希、身份适配与工具次数保持原口径。LME官方裁判口径与LoCoMo官方混合分、语义正确率分别报告。
- 一次冻结实现正式运行，不按分数修改后择优报告。仅技术故障允许修复重跑，保留中断和成本记录。按对话/历史簇给出配对变化与bootstrap区间，并列出退步例子。

## 验证与交付

运行记忆与统一画像回归、时间/乱序更新测试、检索来源多样性及隐私删除测试、生产上下文接线测试；对旧库副本验证迁移幂等与无删除复活。追加真实DSH自动上下文/主动回忆检查，不将兼容循环的整批成绩写成完整DSH或微信端到端成绩。

交付版本源码快照、题目清单、逐题结果、资源统计、比较报告、版本迁移与回退文档。仅更新工作区，不部署生产、不重启服务、不提交Git。若效果没有全面提升，明确报告收益与退步，不承诺分数必然上涨。

## 执行期间追加的独立迁移诊断

主正式运行启动后、尚未形成主结果结论时追加：用SQLite backup API复制2.1的52个测试库，在副本上升级2.2，只运行旧160题的memory回答与评分，不重新提取历史、不重跑none/oracle。启动前方法与时间另存 `migration-diagnostic-plan.json`。这组诊断用于估计旧库直接升级的读取收益，单独报告160份结果，不混入预先固定的582份主结果或新34题留出。原库保持不变，诊断也不触及生产库。
