## 本轮实现

只改读取，使用2.6的52个记忆库副本，没有重新提取。选择器从已授权目录选记录并摘取原话；宿主逐段核验并返回实际连续原文，不能接受模型生成的事实、角色或日期。空白格式差异映射回原文；同记录重复片段合并，避免覆盖。目录显式包含说话角色，区分本人陈述与助手建议。

新增确定性日历释义，用每条原话自己的asserted_at解释“昨天、这个月、几天/几周前”等表达，保留原句。它只解释字面日期，不证明事件发生、不处理有歧义的上周几/上周末、不为多来源画像套用统一锚点。自动画像增加同会话的原话日期，跨会话共享不暴露来源时间，原有冲突/过期观察排除规则不变。

目录预算96000→160000字符，原文窗口400→600字符，选择器输出600→2400 token；最终回答记忆仍约6500字符、最多12项，最多两次主动回忆，没有新增第二次选择模型调用。删除、纠正、停记及来源到期时的调用前后核查保持不变。

## 结果分析与退步

与2.6首次相比，2.7首次LME2题转对、5题转错，LoCoMo3题转对、7题转错。不能把“两次过线”写成全面提升，更不能只比较2.6的较低重复分数。目录、摘录、日期及提示一起改变，未做消融，不能把变化单独归因于其中一项。

目前仍有三类具体问题：

- 选择器可能没选出建议所需的背景约束。例如手机配件题没有返回已有手机型号；“没有现成推荐”不能等同“没有相关记忆”。
- 片段选择可能遗漏事件顺序或限定，更多摘录不保证更好的整体理解。
- 证据已给出，回答仍可能计算或判断错误。例如咖啡水量题写出“从6盎司变成5盎司”，却判断成“更多水”。这类错误不能只靠继续扩大存储解决。

这几轮共同说明：入库保真、互补证据覆盖、回答对证据的正确使用分别需要验证。LongMemEval的重复分数已接近门槛，不代表统计上能保证每次过线。回答和裁判使用同一模型，语义评分也有噪声；结果不是独立人工评审或公开排行榜成绩。
