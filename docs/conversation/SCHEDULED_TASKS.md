# 定时和周期任务

由原有3秒轮询驱动，无新增线程或调度服务。真实消息发送者在当前会话的好感度严格超过`bot.json`的`scheduler.min_affinity`（默认50）后才开放`manage_schedule`。昵称、备注、正文中的身份声明不能授权；分数由统一成员记忆模块读取，不交给模型判断。默认关闭，并要求启用`member_memory`。每项操作绑定发起消息所在会话，不允许模型传入目标群。

可以叫“影”或真实@后说：

- “影，十分钟后提醒我起来活动一下。”
- “影，每天上午9点搜索当天AI新闻，简单说三条并带来源。”
- “影，每周一早上8点提醒我开周会。”
- “影，每隔30分钟提醒我喝水。”
- “影，列出本群任务。”
- “影，把读书提醒改到每天晚上10点。”
- “影，取消喝水提醒。”

任务ID仅保留在工具调用、数据库和日志中；普通确认、列表和定时发送不展示ID。按内容修改或取消时，AI先查询当前群任务并匹配，多个匹配则澄清。列表可用临时序号；“取消第二条”必须对应最近一次实际展示的列表内容，再查当前任务核对，不能直接取数据库当前第二条；缺少历史列表时需要澄清。执行成功后才自然确认结果。

默认北京时间。支持一次、每天、每周指定星期和固定间隔；间隔至少5分钟，最多20项启用任务。单次时间限未来一年。`remind`直接发保存的正文；`ask_ai`在到点时生成回答，允许现有搜索和天气工具，不读取群历史，也不提供任务管理、表情或任意代码能力。AI任务与普通回答串行执行，所以实际时间受API和桌面发送耗时影响，不是硬实时调度。

SQLite的`scheduled_tasks`保存计划，`scheduled_runs`保存每次到期执行，`schedule_operations`按真实源消息和参数去重。占用一次执行及推进下次时间在同一事务完成。重复工具调用不会重复创建同一任务。任务修改替换完整规则；取消立即停止未来执行。

重启时将中断的执行标记为`interrupted_uncertain`，不重试；已有确认则保留`confirmed`。超过5分钟的错过执行标记`missed`，循环任务跳到下一次未来时间。客户端未登录或群校验失败时不发送。桌面发送沿用原来的群校验和数据库回执确认，失败/不确定不自动重发。`completed`仅表示单次时间已经消费，送达请看`last_run_status`。

权限、参数及持久化由代码执行，不靠人格提示词保障。计划管理只在达到好感门槛的成员当前提问含任务相关意图时开放；表达不明确时请叫影并说明提醒、任务或周期。任务内容最多500字。未达到门槛的成员不能创建、修改、取消或查询任务。权限只决定管理入口；已经成功建立的任务会继续按计划执行。
