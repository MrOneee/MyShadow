# 统一成员画像

同一机器人账号下，使用成员微信 ID 识别同一个人，不按昵称合并。基础画像统一维护，但读取仍受来源范围和本人授权约束。不同机器人账号的身份不合并。

## 数据范围

| 数据 | 存储与可见性 |
|---|---|
| 兴趣、明确背景 | 按成员统一，保留每条来源、主题、版本与可见范围 |
| 本人私聊 | 可以读取自己的跨会话基础画像；不搬运群里的经历、关系或称呼 |
| 群聊 | 默认只读取当前范围资料及本人明确共享的基础资料 |
| 称呼、交流偏好、交往边界 | 保留在人设 + 会话范围内 |
| 好感、熟悉度、共同经历 | 保留在人设 + 会话范围内，不跨群累加分数 |

在群 A 说“我喜欢摄影”，本人私聊可以知道这项偏好，群 B 不会自动知道。明确说“允许把我喜欢摄影共享到其他群”并且工具成功后，其他群才能使用。说“撤回摄影的共享”可以取消授权。私聊本身不表示同意公开。

私聊纠正“现在不喜欢摄影了，只在这里说”，会让群 A 的旧结论失效，但群 A 不会收到新的私聊内容或私聊来源。既保持基础事实一致，也不把私聊当作公开消息。

## 合并、纠正和删除

基础事实使用成员、类别和主题关联。相同主题下的重复事实在展示时去重，原始来源仍保留。明确纠正会建立替代关系；新值默认保持当前来源的可见性，不继承旧值的共享授权。历史替代链指向最新版本，防止经由中间版本泄漏隐藏纠正。

没有明确纠正意图的冲突标记为“待确认”，不会自动注入成确定事实。旧消息迟到不能覆盖新纠正；跨会话修改会更新版本屏障及读取缓存，阻止正在执行的旧提取重新写回过时结论。

“忘记我喜欢摄影这件事”删除该基础主题的版本及相关派生记录；不影响无关兴趣。无具体内容的“忘记我”仍清除当前会话来源记忆并停止当前范围记忆，不表示清除所有会话。微信原始聊天、短期上下文及运维备份不属于此操作的清除范围。

## 实现

`member_profiles.py` 在现有 SQLite 中实现身份、主题关联、可见性、去重和版本处理；`member_memory.py` 负责提取、工具与上下文集成；`member_memory_policy.py` 说明模型的使用边界。没有新增常驻服务或向量数据库。未使用设计模式：直接实现更简单。

宿主绑定真实成员与会话，私聊归属由会话 ID 与发送者 ID 判断，不接受模型自行指定。自动提取只接受白名单字段，不能授予共享权限。旧库增加字段并保留旧事实，默认全部为原范围可见，不自动公开。读取先过滤权限，再排序和限制数量。

## 能力边界

同一个微信 ID 能稳定对应同一身份；不同微信账号不会因名字或内容相似被自动合并。事实主题依靠模型提取及确定性文本处理，不能保证任意同义表达都自动合并。不能确定时保留冲突、要求澄清，避免错误覆盖。模型仍可能理解错误，用户可查看、纠正和删除。

- 真实 DSH 三项通过：普通工具模式共享、PTC 模式回忆、普通工具模式撤回共享。全程采用临时合成用户，没有发送测试微信消息。
- 模型提取、DSH 工具、部署及服务复核会生成本地 JSON 验证结果；这些文件可能带有环境元数据，不进入公开仓库。
