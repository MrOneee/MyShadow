# 按群绑定的个人背景

实验室0号绑定 `knowledge/jiangcheng`。其他群没有该绑定，因此不会收到这里的核心背景、自动召回内容或查询工具。

## 组成

- `personas/jiangcheng.md`：说话与行为习惯、工具使用规则。
- `knowledge/jiangcheng/core.md`：每次放入 system 的核心身份、当前关系与时间基准。
- `knowledge/jiangcheng/cards.json`：人物概览、主题概览和按经历顺序排列的记忆卡。
- `knowledge/jiangcheng/aliases.json`：别称、人物名和常见指代映射。
- `knowledge/jiangcheng/index.sqlite`：中文双字词 FTS5 索引，只读打开，不每轮载入全部卡片。

## 请求中的位置

`system = 人设正文 + 核心背景 + 活动能力说明 + 本轮时间/权限规则`。

命中明确人物名或别称时，最多自动召回两张卡，总正文不超过1000字，放在聊天背景的 user 数据消息中。卡片不是新的系统指令。当前提问仍保持最后一条 user 消息。

`search_background(query, limit)` 查询绑定背景，每轮最多两次，每次最多四张卡、正文总计不超过2600字。返回状态区分空结果、读取失败和没有绑定；`partial`、`more_matches` 说明截断和更多结果。目标背景由宿主绑定，模型不能指定群、文件或数据库。

普通回复、主动发起、定时AI任务都可以使用背景核心；参与决策也会收到核心关系。聊天与定时AI任务按本轮提供的工具查询。资料整理路径保留该只读工具，兼容 native 和 PTC 的只读白名单。

本群上下文预算为20000，其他群保持原值。预算由群配置控制，防止核心背景和自动召回挤满原有历史额度。索引缓存上限512 KiB，每次读取后关闭连接。

## 内容质量与维护

输入按物理顺序编号，重复编号不覆盖。分段提取后核对原文证据，再审核事实、人物归属和蒋丞可知视角。人物/主题概览的各条陈述关联已审核事实，并再次核对支持关系。未经确认的即时位置、工作细节和新进展不写入。

离线证据和审核结果保存在 `.remote-work/background-audit.json`，不注册为聊天工具，不放入发送给模型的背景目录。生产构建记录位于服务器 `logs/background-build`。运行时仅发布审核后的概括卡片，不发布输入全文。

修改人设、核心背景或卡片后，先运行回归与内容验收；卡片变化需调用 `background_knowledge.build_index(directory)` 重建索引，再一起部署并重启。单改人设不需要重建索引。原文核对失败不能用自由编写的细节替代。
