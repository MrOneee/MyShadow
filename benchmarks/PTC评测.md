# PTC 接入与小样本评测（2026-09-09）

已接入真正的 DSH PTC：模型调用 `run_code`，通过生成的工具 SDK 调用只读工具。
使用 QuickJS/WASM 后端隔离程序，不开放 Node/文件/进程/直接网络。
普通聊天与发送保持 native。线上默认 `harness.research_mode=native`，PTC 保留为实验选项。

## 方法

- 共 18 次对照运行：16 次固定合成资料任务，2 次真实网页任务。另有服务器真实 PTC 冒烟测试。
- 固定资料包含四页共 160 条作品记录，要求筛选完整汤面/汤底且达到评分要求的 ID；历史任务包含两段共 20 条合成消息，按书名去重统计推荐人数。不是现实海龟汤或真实群聊。
- 同一任务、模型、资料、结果 schema、工具预算；每组 native/PTC 各两次，顺序交替。网页各一次。
- 首轮发现 PTC 倾向打印全文，随后加入通用“先看字段与少量样本，再编程筛选”的指引，保留首轮与复测，未删除不利结果。
- 模型为线上聊天使用的 Flash，以及海龟汤使用的 Pro。关闭额外推理，最多 12 步、16 次工具调用；合成工具固定短延迟，不代表真实网站延迟。
- 在 Windows 本机运行；时间包含 SDK 启动。部分资料复测与独立网页评测有时间重叠，因此小样本耗时只能作为线索，不能视为稳定性能指标。
- Token 是主 Agent 各轮上报的累计用量，包含反复输入的上下文；不包含网页搜索服务内部模型的隐藏成本。
- RSS 每 50 ms 采样一次 Python 与其子进程之和，不是线上容器增量，也不是 QuickJS 堆用量。

## 结果

时间与 Token 为每种模式的均值。固定资料结果全部正确；这里不把“交出 JSON”当作成功，筛选 ID 和统计数有固定答案。

| 任务/阶段 | 模型 | 每模式次数 | native 秒 | PTC 秒 | native Token | PTC Token | 正确数 native/PTC |
|---|---|---:|---:|---:|---:|---:|---|
| 资料筛选初测 | Flash | 2 | 8.13 | 20.68 | 10,730 | 15,928 | 2/2、2/2 |
| 资料筛选指引调整后 | Flash | 2 | 9.35 | 16.43 | 10,838 | 35,058 | 2/2、2/2 |
| 群历史统计初测 | Flash | 2 | 13.59 | 8.07 | 3,571 | 6,950 | 2/2、2/2 |
| 资料筛选补测 | Pro | 2 | 10.74 | 12.02 | 10,478 | 8,212 | 2/2、2/2 |
| 真实官方文档检索 | Flash | 1 | 170.12 | 101.63 | 91,072 | 118,827 | 0/1、0/1 |

真实检索要求查到官方文档并核对工具模式和并发默认值。native 答错默认值；PTC 虽答对数字，但抓取记录未取得支撑该字段的内容，不能排除猜测，因此也判失败。原始评测最初只检查字段值，报告额外审查了来源，将 PTC 的这次结果从“值正确”改为“不通过证据核验”，没有重新跑到成功为止。

Pro 资料筛选的平均 Token 减少约 **22%**，但两次结果分别为约 +4% 和 -47%，收益并不稳定，平均耗时增加约 **12%**。Flash 历史统计速度较快，但 Token 增加约 **95%**。Flash 资料筛选反复读取/打印全文，甚至触及预算后才提交；调指引并未消除这种行为。

内存：PTC 的整个测试进程树峰值范围约 **188–203 MiB**；native 多数为 **169–182 MiB**，另有两次首次启动峰值 **262 MiB、305 MiB**。因此不能据此宣称 PTC 省内存；排除启动波动的后续运行常见约 15–25 MiB 额外占用，但需要独立更大样本验证。

## 决策

保留通用只读 PTC 路径，**不默认替换线上 native**。当前仅观察到 Pro 在部分资料任务上的 Token 收益，没有稳定的整体收益证据。网页可达性和资料完整性仍是检索瓶颈；PTC 不解决这些问题。现有历史工具每轮最多两次、每次最多十条，也限制了批量编排能发挥的空间。

## 复现

在有 `deepseek-harness-sdk==0.1.2rc1` 的 Python 环境安装评测依赖 `psutil`；在 `agent_runtime` 目录运行 `npm ci --ignore-scripts`。从仓库根目录执行：

```text
python benchmarks/ptc_eval.py --case all --repeats 2 --ai ai.json --output logs/ptc-eval-new
python benchmarks/ptc_eval.py --case pages --model deepseek-v4-pro --ai ai.json --output logs/ptc-eval-pro-new
```

每次运行生成独立的任务键，不复用完成结果缓存。只使用合成群和只读工具，不向微信发送消息。
汇总的逐次数据见 `ptc-results-20260909.json`，保留阶段、模型、结果、错误、时间和 RSS。
