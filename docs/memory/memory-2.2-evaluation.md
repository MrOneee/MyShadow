# 记忆系统 2.2.0 优化复测报告

日期：2026-10-22。结论：本轮改善了状态版本维护、相关证据组织和部分时间题，工程回归通过；准确率收益有限，**不能认定全面优于2.1.0**。原160题中LME语义正确25→28，LoCoMo 59→60，但LoCoMo官方混合分37.77%→35.81%。新增34题表现更好，样本仍不足以证明稳定泛化。源码已更新至2.2.0，未部署生产。

## 本轮改动

- 按多个关键词扩充有界候选，在权限过滤后按词的重要性、问题覆盖和来源重复程度选择证据；增加同主题可见新旧版本，避免只看到失效旧值。相同文本来自不同事件时仍分别保留。
- 提取器读取与新消息相关的旧主题，保留具体实体与列表，区分累计、增量、目标、建议和实际事实。普通矛盾保持待确认；明确更新按说出时间维护版本，同值明确确认也保存证据，迟到更新只补历史区间。
- 读取提示要求逐项核对对象、数值、单位、时间与比较方向，缺项时补检索。相对日期使用原话时间锚点。这是提示约束，不是确定性的事实验证器，复测仍出现数值/日期推理错误。
- 维持隐私、共享、停记、删除规则。单次回忆最多12条、正文片段600字符、整体6500字符；2.1上限为6条。自动检索次数与最多两次主动回忆不变，但候选计算量增加。

详细方案见 [执行前方案及追加诊断说明](memory-2.2-plan.md)，行为、迁移和回退见 [版本记录](MEMORY_VERSIONS.md)。未使用设计模式，沿用小型函数和既有版本机制。

## 方法与完整性

原126题和上轮34题均已分析过，本轮合称160题回归集，不再称上轮34题为盲测。实现前另固定34题：LME七层各2题，LoCoMo五类各4题，种子20261024，排除前160题。LoCoMo仍来自相同10个对话，是问题留出，不是对话独立验证。

新版194题从完整历史写入66个隔离库，每题运行无记忆、标准证据、记忆三条件，共582份回答/评分。冻结2.1实现同期运行新增34题，获得102份控制。主运行期间追加旧库升级诊断：复制2.1的52个库，只升级副本读取逻辑，另跑原160题memory条件，不重新提取历史。三组分别存放，全部完整且没有接口、回答或评分错误；正式源码冻结后没有按分数调参重跑。

数据沿用已冻结的 [LongMemEval cleaned](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned) 与 [LoCoMo](https://github.com/snap-research/locomo)。提取、回答、裁判均为deepseek-flash，temperature=0、thinking关闭，官方评分源码与数据哈希不变。LME采用官方裁判提示口径；LoCoMo同时报告语义裁判与官方混合分（可回答题分类F1、对抗题规则分），不能把混合分称为F1。

## 退步、推理与裁判复核

复核由执行代理完成，不是独立人工盲审；未改写任何自动评分。详见manual-review.json。

- LME `4b24c848`（H&M累计数量）、`603deb26`（调酒累计次数）保持正确，新版直接回答当前累计值；它们不是本轮新增正确题，不能当作准确率提升来源。
- LME `6071bd76`仍错：证据含每汤匙6盎司变5盎司，回答却仍说“更多水”。新增核对提示没有解决这个比较方向错误。
- LoCoMo `0:161`仍对缺乏依据的碗的意义作推断，说明拒答约束仍会失效。
- LoCoMo `2:124`被计为本轮语义提升，但新旧回答都只是泛称玩游戏、吃东西，未补出标准答案的charades和scavenger hunt，官方F1不变。这是裁判宽松或不稳定的具体例子，不能作为明确实质进步。
- 旧库升级诊断出现“证据没有返回”和“证据已返回却判断错误”两类退步：如排班/披萨信息漏取；书籍先后顺序与相对日期解释错误。增加候选和提示并未彻底解决这两个层次的问题。
- 完整重放的退步另有不同原因：`4f54b7c9`已返回多条家传物件信息却漏计；`2:70`已有披萨原话，但事实带待确认标记后仍拒答；`6:114`未返回旧版明确的“明天打电话”片段。不能把旧库诊断的根因直接套给完整重放结果。

官方F1下降也不全等于事实更差：迁移诊断中有4题仍被语义判为正确，但回答变长、增加解释，使F1下降；它们合计贡献约−2.23个百分点，其他题净抵消部分下降。另一方面确实存在漏项和检索遗漏，因此不能把全部退步归结为措辞。复核同时保留“近义答案从no变yes”和“未完整列出标准答案却判yes”的例子，语义分与F1需要一起阅读。

当前仍依赖词面匹配和模型对主题/replace语义的判断；同义改写、跨语言缺乏共有关键词仍可能漏召回。事实每人每批最多6条、单条100字、引文最长200字符，密集列表仍可能写入不全。生产敏感过滤保持开启，某些公开基准问题因此不可覆盖。诊断的来源命中重建是偏乐观估计（尤其LME按会话来源），不能视为精确证据Recall或错误原因百分比。

## 成本与验证

相同160题、包括写入/三种回答/评分，总token为8,125,011→9,860,194，**增加21.36%**；请求数3283→3282。数据库合计65.69→66.22 MiB，事实6141→6283，经历10260不变。共享LoCoMo历史的全部写入成本计入160题，两版口径相同。

记忆回答中位耗时：LME 0.933→0.765秒、LoCoMo 0.902→0.840秒；P95分别1.782→1.573秒、1.490→1.549秒。本地读取中位耗时约14.0→27.1毫秒、9.7→13.8毫秒。端到端时间受网络/服务波动影响，不据此宣称变快；本地检索工作量确有增加。

本轮已知实际用量：新版194题12,476,708 token；旧版新题控制3,098,114；旧库迁移诊断656,426；合成资料提取及两项真实DSH检查9,306；合计 **16,240,554 token**。不含此前两轮评测，没有按未核实单价估算费用。

82项相关测试通过，包括新增10项证据检索测试、9项状态更新测试及原记忆/统一画像/评测/生产消息接线回归。冻结前修复了同主题继任值漏检、跨事件正文误去重、预算顶层开销、跨来源陈述时间暴露和乱序历史区间问题；正式运行一次完成。源码语法检查与diff空白检查通过。

真实DSH（项目固定0.1.2rc1隔离Windows依赖）两项检查通过：自动上下文回答累计7件，0工具回调；主动回忆通过2次实际回调，回答2026-10-19与6号圆头画笔。第一次中文查询为空、第二次英文查询命中，也暴露纯词面检索的语言限制。整批582份采用兼容工具循环，不能称为整批DSH或完整微信端到端成绩。完整Bot集成仍受Windows的fcntl导入限制，使用实际消息构造方法的隔离测试补充验证。

迁移在旧库副本验证：98条事实、241条经历及证据、状态、其他表内容保持不变，仅版本标记升级；第二次幂等，原库未改变。补充诊断另核对52个旧库前后逻辑哈希。没有生产迁移、部署或服务重启。

## 版本结论与交付

2.2.0已实现并完成评测，可作为候选版本审阅；鉴于LoCoMo回归F1下降、token增加和语义提升区间跨0，本次不作“全面优于2.1、可直接推广上线”的结论。后续应优先处理遗漏具体实体和跨记录证据选择，增加独立中文/新对话验证；数值与日期错误也需要比单纯提示更可靠的约束。不要继续在同一小题集上反复调参后择优汇报。
