# 记忆系统 2.1.0 优化复测报告

日期：2026-10-22。结论：问题相关自动检索和保留原文证据明显改善了本次样本的可回答题表现，额外留出题也有提升。跨会话综合、冲突消解和缺乏证据时的拒答仍有不足。本次完成工作区优化与验证，未部署生产服务。

## 变更与评测方法

执行前方案见 [2.1.0方案](memory-2.1-plan.md)，原始对照见 [首次报告](benchmark-report-2026-10-22.md)。新版加入当前问题驱动的自动检索、同成员同来源会话的事实引文索引、较完整的有界经历和命中片段；完善提取/读取提示及删除索引清理。旧库升级与回退见 [版本记录](MEMORY_VERSIONS.md)。

主评测沿用原126题：LongMemEval-cleaned 28题、LoCoMo 98题。另在修改前固定34道不重叠留出题（14+20，种子20261023），并用冻结的旧实现重新运行留出对照。所有历史按顺序写入全新隔离库，问题与标准答案不进入记忆写入。新版共160题，每题无记忆、记忆、标准证据三种条件，共480份回答及评分；旧版留出对照102份。两批均完成且没有接口或评分错误。

提取、回答和裁判均使用 `deepseek-flash`，temperature=0、thinking关闭。LME使用官方裁判口径；LoCoMo同时保留官方混合分数（可回答题F1、对抗题规则评分）和语义裁判正确率，两者不可混称。题目、数据及评分源码SHA256、模型配置、逐题回答和代码快照均存档。数据来源为 [LongMemEval cleaned](https://huggingface.co/datasets/xiaowu0162/longmemeval-cleaned) 与 [LoCoMo官方仓库](https://github.com/snap-research/locomo)；本次沿用首次冻结数据，未重新选择数据版本。

## 主样本结果

以下均为记忆条件；不能将两个数据集直接合成一个总体能力分数。

| 指标 | 旧版 | 2.1.0 |
|---|---:|---:|
| LME全部题正确率 | 7/28，25.00% | 16/28，57.14% |
| LME可回答题正确率 | 3/24，12.50% | 12/24，50.00% |
| LME不可回答题拒答正确 | 4/4 | 4/4 |
| LoCoMo全部题语义正确率 | 24/98，24.49% | 47/98，47.96% |
| LoCoMo可回答题语义正确率 | 4/78，5.13% | 28/78，35.90% |
| LoCoMo对抗题拒答正确 | 20/20 | 19/20 |
| LoCoMo官方混合分数 | 23.01% | 36.07% |
| LoCoMo可回答题官方F1 | 3.27% | 20.96% |

配对比较：LME有9题由错变对、0题退步；LoCoMo有25题由错变对、2题退步。以历史/对话为簇进行4000次配对bootstrap，全部题正确率差的95%区间分别为 +14.29～+50.00、+14.29～+31.63 个百分点；仅反映这些抽样历史上的不确定性。

新版LME各类正确数（每类4题）：拒答4、知识更新2、多会话0、助手信息3、偏好2、用户信息4、时间推理1。LoCoMo：多跳2/20、时间9/20、常识5/18、单跳12/20、对抗19/20。多会话和多跳仍是主要短板。

无记忆正确数保持LME 4/28、LoCoMo 20/98；标准证据条件LME保持24/28，LoCoMo由75/98变为72/98。后者说明即使temperature=0，运行与提示差异仍存在，不能把每道变化都归因于检索。

## 案例复核与残余问题

复核由本次执行代理完成，不是独立人工盲审，未修改裁判分数。逐例见交付资料的 `manual-review.json`。

- LME `4b24c848`：从无法回答变为回答H&M已买五件上衣；证据可达性改善，但真实DSH检查仍对三件/五件记录要求确认，累计状态语义尚未完全解决。
- LME `545bd2b5`、`60d45044`：分别正确找回Instagram每天两小时和偏好的日本短粒米。
- LME `6071bd76`：已找回原先被180字符截断遗漏的咖啡比例，却将每汤匙6盎司变5盎司误说成“更多水”。有证据仍可能推理错误。
- LoCoMo `0:161`：退步，对没有足够证据的碗的意义回答“艺术和自我表达”；需要更严格的证据充分性判断。
- LoCoMo `2:124`：退步，泛化回答玩游戏和吃东西，遗漏charades与scavenger hunt。摘要概括仍会丢失关键细节。

后续优先处理有依据的累计状态替换、可追溯的多会话证据组合及拒答校准；应增加新的独立对话验证，避免继续在同一小样本上调参。

## 成本与运行表现

按相同主126题比较，包含写入、三种回答与裁判的总token由5,472,693升至5,899,385（+7.80%）；调用数2422→2412。对应数据库合计31.98→45.97 MiB，约+43.8%。新版保留更完整证据并抽取更多事实，因此存储增加。

记忆条件端到端回答中位耗时：LME 0.736→0.948秒，LoCoMo 0.758→0.902秒；P95分别1.877→1.484秒、1.569→1.563秒。样本量与网络波动限制解释，不据此声称速度提升。自动检索增加本地工作；主样本模型主动回忆调用LME 4→0、LoCoMo 16→10，新增自动检索分别28、196次（LoCoMo两个成员）。**检索预算并非完全相同**：旧版最多两次主动回忆，新版增加每成员一次自动提供资料。

本轮实际已知用量：新版160题8,125,011 token；旧版留出3,167,920；中断预运行1,257,417；两次DSH检查6,482，合计12,556,830 token，不含中断时可能未记录的在途请求，也不包含首次基线费用。未估算未经核实的货币价格。

## 工程验证与交付边界

63项相关测试通过，覆盖原记忆/统一画像、评测适配、检索权限、部分删除、不同类别共享来源的引文清理、停记、预算、迁移幂等及生产消息构造接线。修改模块语法检查通过。

隔离旧测试库迁移验证：事实70条、经历241条保持不变，经历字符83,451→240,762；第二次初始化不重复修改，首次迁移约0.066秒。只升级备份副本，未碰生产库。正式运行前发现跨类别引文删除残留，修复并增加回归测试后，从干净目录重新评测；中断结果未参与正式评分。

另外安装隔离的项目固定版本Windows DSH运行包，实际执行两项检查：自动上下文正常回答；显式回忆实际调用一次 `recall_memory` 并返回证据。整批评分采用兼容工具循环，**不是整批DSH或完整微信机器人端到端评分**。完整Bot集成测试在Windows因 `fcntl` 导入受限，未声称全项目测试通过；生产 `messages_for` 使用实际方法体的隔离测试验证接线。

本次是小规模分层抽样与问题留出复测，不是两个数据集全量榜单。写入/回答/裁判使用同一模型存在共同偏差；LoCoMo多人适配与官方单一管线也不同。没有新增中文独立数据，不能据此推断真实微信中文场景达到相同正确率。
