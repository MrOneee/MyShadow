## 实现与原因

已确认助手回复原先只保存前800字符，后部信息在入库时就丢失。2.6把上限提高到4000字符，用户正文仍1000，完整输入资格筛查和确认条件不变。新经历记录宿主生成的用户/助手文本偏移量；读取时按角色返回多个600字符互补窗口，最终仍最多12项、约6500字符。角色由宿主绑定，不能用正文里的伪造分隔符冒充助手回复。

本次LME输入的助手回复截断次数从2.3写入的8609降到21；提取批次2009→3125，事实3579→4727，独立证据7537→8632。长回复不仅保留了更多文本，也减少单批被压缩的消息数，不能把全部收益只归因于检索窗口。

相对2.5首次，LME3题转对、2题转错，净增1；转对包含长篇已确认方案的具体数量及个性化建议。LoCoMo9题转对、3题转错，净增6（可回答净增4、拒答净增2）。**LoCoMo本身没有助手回复，本轮又重新提取了相同历史，因此其变化不能直接归因于长回复改动**：独立证据2317→2340、事实1498→1537体现了提取波动。完整逐题胜负保留在goal-metrics.json。

首次剩余LME错误包括家传物品计数时列出五项却给“四件加一件可能算”的含糊答案、相对日期换算错误和缺少时间线而拒答。没有修改裁判或剔除这些题。LoCoMo仍有长列表遗漏和多步推断不足。

## 验证与版本更替

105项相关测试通过。新测试覆盖长确认回复尾部可检索、角色标记伪造、经历专有内容按描述忘记时同步清理来源和索引、长输入提取预算；既有权限、停记、调用中删除、更新历史和生产接线回归保持通过。

真实DSH三项检查通过：最新累计值、主动回忆日期/细节、位于长回复后部的825毫米参数。使用合成资料及隔离依赖，没有启动完整Bot/微信。2.5→2.6隔离升级除版本标记外所有表内容保持一致，重复初始化幂等，源库不变。

旧库升级不会补回已截断内容，也不会自动给旧经历补角色偏移。新基准的完整重写收益不等于现有库直接升级的收益。版本与回退记录见[MEMORY_VERSIONS](MEMORY_VERSIONS.md)，没有部署生产或提交Git。

## 成本

首次全流程4039次请求、19,090,260 token：提取14,878,507、语义选择3,683,396、回答503,794、裁判24,563。与2.3完整提取的9,860,071相比，写入token增加约50.9%；LME数据库总大小72,310,784→123,985,920字节。更完整的记忆有明确的计算与存储代价。

首次LME/LoCoMo读取中位延迟约1.35/2.05秒，含语义模型调用。DSH补充验证另用21,257 token。独立重复和新题确认的成本完成后单列，不把复制库的原提取计为重复运行新成本。

## 独立重复与新68题确认

固定160题独立重复已完成，使用本轮记忆库副本，重新选择、回答和评分，结果为LME32/36、LoCoMo54/92。拒答仍6/6、25/26；LoCoMo可回答官方F1为27.87%。606次请求、4,209,026 token，无API/评分错误。首次和重复的评分不能混合择优。
