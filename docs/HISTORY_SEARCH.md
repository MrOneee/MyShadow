# 查询当前群历史

`search_history(query, start?, end?, sender?, limit?)`是只读工具。由真实触发消息绑定当前群，所有成员可以在当前群询问；无需任务管理员权限。不接受群ID、路径、SQL，也不能查私聊或其他群。自动发起和定时任务不开放此工具。

用法：
- “影，查一下上周大家关于开会的消息。”
- “影，昨天Mr.One提过什么时间安排？”
- “影，查8月1日到8月7日关于露营的讨论。”

默认查提问前7天，单次区间最多31天，允许指定更早的日期。北京时间；start包含起点，日期形式end包含当天，时间形式end不包含该时刻。始终排除当前提问及之后的消息。关键词是解码后的字面包含、忽略大小写，不是语义检索。sender在本群成员昵称、群昵称、备注中精确匹配，重名或不存在则不猜测。

支持普通文本、引用消息自己的正文、链接标题、简介和URL、文件标题，以及微信为部分动画表情附带的弱描述。不会从引用XML冒认被引用消息的作者，也不把表情描述当作画面识别结果；图片、语音和视频仍不解读。结果带显示名、北京时间、类型和截短文字，不暴露内部微信ID、分片路径或数据库ID。

每轮最多两次不同查询，相同参数复用本轮结果。默认返回5条，最多10条，每条最多400字，总文字最多1600字。查询最多扫描3000条候选、8个分片；逐个打开并关闭快照，不常驻缓存整库。扫描设置约12秒软时限，快照解密本身可能使总耗时超过该值。排序为已扫描结果的新到旧；分片预算耗尽时不保证全库最新或查全。

`partial`表示有分片/消息没有读完、读取失败或达到扫描预算；`more_matches`表示匹配结果受返回数量/总长度限制；单条`truncated`表示片段。没有结果不等于从未说过，只有本机客户端保存的记录可查。已有history_exclusions中的错发消息会排除。

配置`history_search_enabled=false`可关闭，默认开启。查询不写微信库、不修改聊天游标，不自动发送消息；最后由原有回复流程回答。
