# 记忆系统 2.1.0 优化与复测方案

日期：2026-10-22。基线为同日首次评测的代码快照和126题结果（文档标签2.0-baseline；此前代码没有正式语义版本）。本方案在本次修改及复测前确定。

## 改动范围

1. 生产 Bot 在装配记忆时传入当前提问。MemoryService.context 在同成员/同会话权限下进行确定性查询，返回有界的问题相关资料；仅关系决策和预算回退的 compact 模式保持轻量。
2. 已确认经历保留现有获准事件中的完整有界正文（用户1000字符、助手800字符），检索时按问题选择片段，而不是固定取开头。普通成员发言仍不能冒充机器人共同经历。
3. 画像已通过证据校验的短引文建立独立检索索引，仅同成员、同来源会话可按引文召回/展示；跨会话共享仍仅允许画像值，不将整句原文随共享泄露。删除同步移除派生索引。
4. 提取提示强调一条事实一个主题、明确变化/累计用同主题replace、记录来源时间供时间线解释；不做“新信息无条件覆盖旧信息”。无法判断的矛盾继续待确认。
5. 添加版本标记和幂等迁移。迁移仅扩充仍然存在且能对应现存已处理事件的旧经历、重建引文索引，不创造已删除的事实或经历，不读取微信原始数据库。原始事件已过保留期时不能补回丢失正文。

沿用 selecting-design-patterns 技能的简化原则：未使用设计模式，增加小型检索函数模块，避免新增向量服务或模型依赖。

## 固定评测

- 主回归：原LongMemEval清洗版28题 + LoCoMo98题，完整历史重新写入独立数据库。模型、温度、正式评分规则、题目与身份适配与首次评测保持一致；新接入仅将当前问题传入生产context。历史基线保留，明确其不是同时重跑的控制组。
- 重新运行 none/oracle 两个对照，用于检测当日模型/裁判波动。
- 留出：LongMemEval 每层另抽2题，共14题；LoCoMo 每段对话另抽2题，共20题。种子20261023，从原抽样之外选择，在修改前保存清单。LoCoMo 可复用同对话的新版本记忆；LongMemEval使用14个全新完整历史。三条件均运行。
- 只看一次冻结版本的结果，不针对低分题循环调整后择优。若出现适配器或运行错误，保留记录并说明修正，不把故障样例静默删除。
- 原生工具循环仍不等同于生产DSH；增加生产context接线的针对性验证。若无法取得真实DSH运行环境，不声称已验证DSH端到端成绩。

## 验证与交付

重点验证尾部证据保留、同成员/会话隔离、跨会话共享不泄露原文、删除后不召回、停记、预算边界、旧库迁移幂等、累计更新与未确认冲突。执行现有记忆/画像回归及新增测试。

交付新版本实现、版本与迁移/回退记录、主回归与留出结果、逐题可审阅数据及对比报告。性能和存储增长如实报告；不保证通过隐私限制排除的题型得分。仅修改当前工作区，不自动部署线上或提交Git。
