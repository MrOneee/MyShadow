# MyShadow 项目说明

核对日期：2026-10-22。本文依据当前本地工作区源码、配置示例和启动文件编写，包含工作区中尚未提交的功能；不代表服务器当前启用状态。历史设计、验收记录和 README 中的旧版说明，应结合本文及实际配置阅读。

## 1. 项目定位

MyShadow 是运行在 Linux 微信桌面环境中的 AI 数字分身。它以真实微信账号为载体，读取该客户端已同步的本地聊天数据库，结合人格、背景知识、会话历史和成员记忆生成回答，再操作微信桌面发送。默认人格为“影”，也支持按群切换人格。

项目适用于群聊陪伴、好友私聊、知识问答、历史消息查询、群活动和提醒等场景。它采用现有模型接口、提示词和持久化记忆实现个性化，没有专属模型训练流程，也不是微信官方机器人接口。

主要运行环境是 Linux amd64 + Docker。当前 Windows 工作区可用于阅读和编辑；核心程序依赖 `fcntl`、X11 和 Linux 微信环境，不能直接把 Windows Python 作为完整生产运行环境。

## 2. 系统结构

```text
微信客户端与本地数据库
        │ 只读数据库快照、增量扫描
        ▼
消息采集与触发判断 ──► SQLite 回复队列
                            │ 按会话分配工作线程
                            ▼
             人格 + 背景知识 + 历史/摘要 + 可见记忆
                            │
                            ▼
                AI 推理与受限工具调用
                            │
                            ▼
                微信桌面发送与数据库回执

后台成员记忆整理、梗候选整理 ──► 各自的记忆存储
活动宿主、到期任务             ──► 复用回复与发送流程
```

业务主控是 `myshadow.bot.Bot`。微信数据读取、模型调用、人格装配、记忆和工具分别拆在领域模块中；主控仍承担较多上下文和任务协调逻辑。[架构评估](architecture/ARCHITECTURE_REVIEW.md)中的进一步拆分属于建议，不能当作全部已经实施。

## 3. 从启动到回复

### 3.1 启动准备

`start.sh` 检查 Docker、准备私有目录和桌面密码，创建缺失的 `bot.json`、`ai.json`，然后构建并启动 Compose 服务。已有配置不会被示例覆盖。

容器中 `services/weixin-bot` 使用镜像内 Python 环境启动 `myshadow.bootstrap`。初始化依次检查微信是否登录、数据库是否同步、账号是否与配置匹配、模式是否有效、模型配置是否可读，以及数据库快照是否可解密。缺少条件时写入 `bot-health.json` 并继续等待；就绪后切换到 `myshadow.bot run`。

### 3.2 收集消息与决定参与

默认每三秒轮询一次。群列表从当前账号已同步的联系人数据动态发现；私聊联系人仅在启用相应配置后加入。每个会话和数据库分片有独立游标，已处理消息通过持久化位置去重。没有变化且已扫描完的分片会跳过重复解密。

群聊的基础入口检查消息元数据中的真实 `atuserlist`，不会把手写“@昵称”当作真实艾特。启用选择性回复的群还可通过称呼、核实过的引用、短期接续及轻量参与决策触发。启用好友私聊后，无需艾特即可处理新文字、支持的引用、分享链接和图片；语音、视频不会因此获得识别能力。

消息能否触发回复，与是否进入已启用的后台记忆整理是不同的判断；部分普通未艾特文本可用于学习，但不一定产生回复。

### 3.3 组装上下文与调用模型

宿主装配当前人格、背景核心、当前会话近期消息、滚动摘要，以及按权限筛选的成员资料、图片摘要和相关梗。默认上下文预算为 12,800 tokens，可按人格覆盖；工具定义、输出和封装需要预留空间。旧消息超预算时滚动压缩，固定内容仍放不下则返回明确失败，而非无限重试。

示例配置启用 Harness，由它推进模型与工具循环；关闭后保留原模型路径。模型只能获得宿主为本轮开放的工具，实际会话和发送者由宿主绑定。工具成功前不能确认已经执行。

默认两个会话工作线程，同一会话同时只处理一个工作任务；桌面操作全局串行。Harness 通过进程内准入锁限制单个活动实例，因此两个工作线程不等于两个模型任务始终并行。长检索仍会影响其他会话等待时间。

### 3.4 发送与确认

`preview` 保存回复供检查，不自动发送普通回复；`send` 才执行发送。发送前重新验证会话有效性、名称唯一性、窗口标题和桌面状态，分条回复逐条确认。发送后读取目标微信数据库，确认出现对应的自身消息。

回复队列包含 `pending`、`ready`、`sending`、`submitted`、`confirmed`、`delivery_uncertain`、`expired` 等状态；活动和定时任务有各自恢复规则。送达不确定时不自动重发；检测到串会话时启用路由安全锁。数据库读取始终使用快照，不直接修改微信原库。

## 5. 各类记忆的分工

| 资料 | 作用与边界 |
|---|---|
| 微信原始记录 | 本机实际同步的聊天来源；可查询范围受客户端保存情况限制 |
| 短期历史与滚动摘要 | 维持当前会话连续性，按会话隔离，受上下文预算限制 |
| 人格背景知识 | 影或其他人格自己的身份、经历和知识，不是当前成员的个人档案 |
| 新版成员记忆 | 统一基础画像与会话内偏好、关系、经历；先过滤权限再注入 |
| 旧版 SocialMemory | 兼容 Markdown 画像和群内风格，不能与新版 SQLite 机制混为一谈 |
| 梗词典 | 保存概念含义和公开来源，独立于成员画像，不改变好感度 |

示例配置开启新版 `member_memory.enabled`。仅在未启用新版时，旧版 `social_memory_enabled` 才选择旧路径。跨群基础画像并非全部共享：本人私聊可读取自己的基础资料，群聊默认仅使用本群来源或本人明确共享的基础资料；关系、称呼和经历仍受人设与会话范围限制。

用户可按实际开放能力查看、纠正、删除或停止自己的记忆。删除派生记忆不等于删除微信原始聊天、现有短期上下文或备份。定时任务管理由代码绑定真实发送者，并要求其当前会话好感度严格超过门槛，不能通过昵称或模型自行授权。

梗词典将公开核验的网络梗用于全局理解，将用户解释的私人梗留在当前会话。默认七天内至少三条不同消息构成自动候选，后台决策后核验公开来源。自然使用有概率、冷却和过时降频，不单独为了用梗创建主动消息。

## 6. 配置与默认开关

### 6.1 配置文件

| 文件 | 用途 |
|---|---|
| `.env` | 桌面登录凭据、微信账号标识、`BOT_MODE` 等容器环境变量 |
| `bot.json` | 行为开关、轮询、预算、人设、活动、成员记忆和调度 |
| `ai.json` | 模型地址、API 密钥、模型名、输出参数和搜索开关 |
| `meme-settings.json` | 梗记忆门槛、搜索额度、使用概率、冷却和管理员 ID |
| `personas/*.md`、`personas/voices/*.md` | 身份、共享规则与人格专属表达习惯 |
| `knowledge/<人格>/` | 背景核心、知识卡及检索索引，私人材料需单独部署 |

初始化时，非空的 `WECHAT_NAME`、`WECHAT_BOT_ID`、`BOT_MODE` 环境变量会覆盖对应机器人配置。微信内部 ID 不能用昵称或手机号替代。

有命名人格时，系统提示由身份文件、语气文件和共享规则装配；无对应命名配置时再使用默认提示词兼容路径。不能只改 `persona.txt` 就假定所有人格都会改变。

### 6.2 配置示例的默认状态

以下依据当前配置示例和代码缺省值，不代表线上状态。

| 配置项 | 默认值或行为 |
|---|---|
| `mode` | `preview` |
| `poll_seconds` / `max_age_seconds` | 3 秒 / 300 秒 |
| `group_workers` / `context_token_budget` | 2 / 12,800 |
| `harness.enabled` | 开启；示例每轮 12 步、16 次工具、240 秒 |
| `member_memory.enabled` | 开启；旧版 `social_memory_enabled` 关闭 |
| `activities.enabled` | 开启，注册 `turtle_soup` |
| `vision_enabled` / `stickers_enabled` | 关闭 |
| `selective_reply.enabled` | 关闭，默认群列表为空 |
| `private_messages.enabled` | 示例未配置，代码默认关闭 |
| `scheduler.enabled` / `scheduler.min_affinity` | 关闭 / 50 |
| `history_search_enabled` | 开启 |
| `link_reader_enabled` / `realtime_enabled` | 示例未配置，代码默认开启 |

梗记忆的设置文件可在模块已运行时重读。普通机器人配置、人格文本和 Python 业务代码没有统一热加载机制，通常需要仅重启机器人子服务才生效；修改 `.env` 则需重新应用容器环境。`preview` 也不等于完全离线或不写盘，仍可能调用模型、学习记忆和产生私有日志。

## 7. 数据落盘与外部调用

| 路径 | 保存内容 |
|---|---|
| `data/wechat/` | 微信配置、登录态、加密数据库及客户端缓存；挂载到容器 `/config` |
| `bot-state.sqlite3` | 会话游标、回复、摘要，以及启用的活动和调度状态 |
| `member-memory/memory.sqlite3` | 新版成员事实、经历、关系、检索索引和整理队列 |
| `social-memory/` | 旧版画像 Markdown 和队列 |
| `meme-memory/memory.sqlite3` | 梗候选、词条、来源、删除状态和管理去重记录 |
| `harness-data/` | 分会话执行日志、模型任务、工具事件和效果记录；梗搜索在其 `memes/` 下 |
| `bot-health.json` | 最近轮询、模式、错误、会话与部分功能状态；不是完整审计日志 |
| `routing-safety-lock.json` | 路由异常保护标记 |
| `logs/`、`backups/`、`*_keys.json` | 运维资料、备份、数据库或图片密钥等私有数据 |

模型服务会接收到本次推理所需的会话资料、选定记忆及图片或图片摘要。网页搜索应只使用必要的公开关键词，天气查询只需要地点等查询参数。来源过滤和提示词约束不能被视为完美的隐私识别器。

私人配置、聊天、记忆、知识卡、截图、密钥、执行日志和备份不能公开提交。日志归档应单独制定保留策略，不能假设所有 Harness 日志会自动清理。安全约定见 [SECURITY.md](../SECURITY.md)。

## 8. 初次部署

需要 Linux amd64、Docker Engine、Compose v2 和用于初始化的 Python 3.10+。镜像安装 Python 依赖、X11 桌面辅助程序及固定版本的 Harness SDK/运行时；JavaScript 测试和 PTC 依赖准备还需要相应 Node 环境。

1. 准备代码并在项目根目录运行 `bash start.sh`。脚本创建缺失配置；首次构建需要下载镜像和依赖。
2. 在自己的电脑通过 SSH 转发服务器回环端口，例如：

   ```bash
   ssh -N -L 18080:127.0.0.1:18080 <server-user>@<server-host>
   ```

3. 打开 `http://127.0.0.1:18080`，使用 `.env` 中的桌面用户名和密码进入桌面，在微信客户端扫码或手机确认登录。
4. 在 `.env` 填写账号昵称和内部 ID，在 `ai.json` 配置可用接口，保持 `BOT_MODE=preview`。桌面密码、SSH 密码和模型 API 密钥是不同凭据。
5. 检查人格资源。示例中的 `knowledge/creator`、`knowledge/jiangcheng` 为私有资源，不随 Git 提供；需要单独准备，或调整人格配置、移除不使用的 `background` 字段。所有注册的人格都会被装配，未使用的人格若配置了缺失资源也可能导致初始化失败。
6. 重新运行启动脚本应用环境变量，观察 `bot-health.json` 和预览回复，按需开启图片、私聊、选择性参与等功能。确认路由、上下文和模型行为后才切换到 `send`。

Compose 将桌面端口默认绑定到服务器回环地址：18080、18443；项目挂载到 `/bot`，持久化微信目录挂载到 `/config`。示例容器限制为 2 GiB 内存、1 CPU、512 个进程及 1 GiB 共享内存，长任务和并发规划要结合这一预算。

当前 Dockerfile 不单独安装 PTC 的 npm 依赖。准备实验性 PTC 或 JavaScript 测试时，需要按锁文件安装 `agent_runtime/` 的依赖，参见 [运行时说明](../agent_runtime/README.md)。

## 9. 运维与故障定位

以下命令在 Linux 项目根目录执行。查看状态无需重启服务：

```bash
bash compose.sh ps
bash compose.sh logs --tail=80 desktop
cat bot-health.json
```

维护窗口需要应用普通配置或代码变更时，可只重启机器人子服务：

```bash
bash compose.sh exec desktop s6-svc -r /run/service/custom-svc-weixin-bot
```

这与重启或重建整个微信容器不同。部署前备份将修改的代码、配置和相关业务状态；回滚时不要覆盖当前微信登录数据或盲目恢复旧活动库。仅复制文件而未重启时，不得宣称已加载的新功能。

| 现象 | 优先检查 |
|---|---|
| 一直等待初始化 | 健康状态中的登录、同步、账号匹配、接口配置或密钥错误 |
| 收到消息但不回复 | 当前模式、真实艾特、选择性参与范围、私聊开关、消息年龄、群级错误 |
| 回复迟缓 | 长搜索、Harness 准入等待、API 超时、数据库读取和桌面发送耗时 |
| 没有背景或记忆 | 人格与来源范围、相关资源、读取权限、停记状态、证据是否足够 |
| 发送停止 | 重名会话、窗口校验、草稿、路由安全锁、未确认送达的任务 |
| 新配置看起来没生效 | 环境变量覆盖、命名人格实际来源、进程是否重新加载 |

不要通过关闭路由保护或自动重发来处理不确定送达。`python -m agent_runtime --group '<会话ID>'` 可诊断执行记录；涉及微信发送的 CLI 不是无副作用检查，不应与常驻服务并行用于随意测试。

## 10. 测试、评测与后续扩展

CI 在 Linux、Python 3.12 和 Node 22 环境安装依赖并运行 Python、JavaScript 测试。标准命令在项目根目录执行：

```bash
python -m pip install -r requirements.txt
npm ci --prefix agent_runtime --ignore-scripts
python -m unittest discover -s tests -t . -p 'test_*.py' -q
node --test tests/test_ptc_runtime.mjs tests/test_web_result.mjs
```

测试覆盖会话隔离、触发、快照、上下文、记忆、工具桥接、发送校验、活动恢复等；部分集成测试使用本地确定性模型接口，不需要生产密钥。真实联网验收另用隔离目录、合成成员和预览宿主，不向真实群发测试内容。

历史验收报告中的通过数只说明对应日期、版本和环境，不代表当前代码已重新通过全部测试。本文更新只核对说明与源码、路径和链接，不产生新的全量测试结论。[长期对话记忆评测方案](memory/benchmark-plan-2026-10-22.md)是独立的评测计划，不是现成跑分结果。

扩展时按职责选择位置：人格措辞放 `personas/`；背景资料放 `knowledge/`；新工具在业务模块实现，再由宿主绑定权限、参数与预算；有状态群活动通过 Registry/Host 和 `skills/` 接入。新增功能应补到对应分类文档，并更新 [文档目录](README.md)。

## 11. 当前限制

- 非官方客户端自动化，依赖微信数据库格式、客户端版本、窗口布局和桌面缩放；升级可能需要适配。
- 仅能读取当前设备实际同步和保存的数据，不能保证历史查询查全。
- 不支持语音、视频识别；图片需要文件可取得且能解密。
- 搜索、图片、记忆提取和活动判题都可能失败或误判；设置持久化不代表模型判断具有确定性。
- 提醒不属于硬实时调度，API、队列、客户端登录和桌面状态会影响实际送达。
- 本仓库没有把所有线上扩展自动同步回本地的机制；部署前必须比较目标服务器文件，不能用本地旧版本覆盖服务器额外功能。

进一步阅读从 [文档总目录](README.md) 进入；各专题中的“提案”“实现”“验收”表示不同状态，应分别理解。
