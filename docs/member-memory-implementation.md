# 成员记忆、好感与用户画像

## 当前实现

`MemoryService` 统一管理用户画像、确认过的共同经历、关系状态及记忆控制。它接入现有 DSH 回复链路与参与决策，不替换人设、背景知识库、原始历史查询或活动运行器。未使用设计模式：直接实现更简单。

成员身份由机器人账号 + 成员微信 ID 统一绑定，相同昵称不会合并身份。兴趣、背景采用统一基础画像，并按来源和共享授权控制可见性；本人私聊可读取自己的跨会话基础画像，群聊默认只读本群或本人明确共享的资料。详见 [统一成员画像](unified-member-profiles.md)。称呼、边界、共同经历和关系仍按人设标识（默认提示词文件路径）+ 会话 ID + 成员身份隔离。人设文本的小修订保留原有关系；切换到另一份提示词文件或设置不同 `persona_id` 会产生独立关系范围。初始熟悉度为 0，好感为 50，不从旧聊天猜测历史关系。

## 关系怎么变化

| 项目 | 规则 |
|---|---|
| 熟悉度 | 有内容且已确认回复的互动，每半小时窗口最多 +2，每日最多 +4；至少 8 个有效文字，活动互动也可计入 |
| 好感 | 提取器只提议有证据的积极相处、持续摩擦、和解；高置信积极 +1、摩擦 -2、和解 +1，程序执行计算 |
| 防刷分 | 同一来源幂等；同窗口不重复增加；每日好感变化绝对值之和最多 6；7 日内完全重复文本不增加熟悉度/好感 |
| 防误扣 | 默认中性；批评答案、拒绝建议、设置边界、友好互怼不应扣分。摩擦还要求至少两条不同原话证据 |
| 阶段 | 初识；熟悉中（熟悉度 ≥20 且 ≥3 个活跃日）；熟人（≥50 且 ≥10 日）；老朋友（≥80 且 ≥20 日） |
| 最近摩擦 | 48 小时内减少调侃；明确和解可解除。长时间不来聊天不扣分、不催促用户 |

模型只收到自然语言关系简报，不收到数值。例如“熟悉中、友好自然、近期平稳”。好感达到 60 时允许更轻松地接梗，低于 40 时更注意分寸。事实准确性、帮助质量、管理员权限不受好感影响。明确边界始终优先。

参与决策消费同一份简报；熟悉程度不直接换算成发送概率或增加配额。仍需结合实际话题决定是否接话。没有增加主动私聊功能。

## 画像和经历

画像包含称呼、多个兴趣、交流偏好、明确背景及持续交往边界。每项保留来源证据、记录时间、可选生效日期、当前/已替代状态、版本链。本人明确自述与观察分开；观察只用于交流习惯，至少三条不同消息证据，30 天后不再自动注入。

共同经历只从 **confirmed** 回复或已确认的活动交互建立。保存的是“用户问了什么，机器人实际回应了什么”，不凭空写成“成功解决”“玩家获胜”。发送失败、不确定、预览状态不会产生已完成经历。

自动注入优先包含称呼、边界、关系简报及少量画像；更多经历按需用中文 FTS 查询。系统规则放在 system，画像正文和原话作为低信任资料放在 user 资料段。不会把画像当成新指令。当前实现没有向量库；纯隐喻和没有共享关键词的查询仍可能漏召回。

## 用户如何管理

| 表达示例 | 结果 |
|---|---|
| “记住我喜欢摄影” | 保存本人的当前明确原话；实际保存后才确认 |
| “看看我的画像” | 查看本人当前可见的画像；本人私聊包含跨会话基础画像 |
| “允许把我喜欢摄影共享到其他群” | 明确授权后共享这项基础资料；可说“撤回摄影的共享” |
| “把摄影改成徒步” | 唯一匹配后纠正，保留其他兴趣；不明确时询问 |
| “忘记我喜欢摄影这件事” | 删除指定事实及版本链、相关来源和派生经历，保留无关内容 |
| “暂停记忆”“恢复记忆” | 停止使用/写入长期记忆，或从当前时点恢复 |
| “忘记我” | 清除本会话画像、经历和关系，并停记；不会删除微信原始聊天及短期上下文 |

工具为 `recall_memory(query, kind)` 与 `manage_memory(action, description, value, slot, topic, visibility)`，支持 `share` / `unshare`。目标成员和会话都由宿主绑定，模型没有指定他人、群、路径或分数的参数。每轮回忆最多两次；修改工具只在当前消息表现出记忆管理意图时提供。DSH 的 PTC 研究路径可回忆但不能修改记忆。定时任务和活动内部推理没有开放用户画像修改权限。

## 可靠性与资源

消息 outbox 与扫描游标同事务提交。跨库分发至少一次，目标按来源幂等。模型提取在事务外运行，结果提交时检查当前成员版本；忘记/纠正递增版本并阻止迟到提取回写。提取失败保留队列并延迟重试。忘记还清理检索索引、当前工具缓存及旧版 SocialMemory 的派生文件。

SQLite WAL 持久化在 `member-memory/memory.sqlite3`；无全量画像常驻缓存、无新增向量服务。单个后台线程每 5 秒检查本地队列，安静 60 秒、积累 20 条、或最长等待 10 分钟时处理。每次最多 40 条事件、8 位成员，事件与历史画像输入有大小限制。没有新事件时不调用模型。

已处理原始记忆事件保留 90 天，共同经历保留 180 天，操作回执保留 90 天；有效明确画像与紧凑关系账本持续保存，直到本人删除。关系账本保留计算版本用于重建。原始微信历史、DSH 运行日志与已有系统备份由原有生命周期管理，本功能的“忘记”不宣称清除这些数据。

## 启用与运维

在原有 `bot.json` 添加（旧配置不需要重建）：

```json
"member_memory": {
  "enabled": true,
  "shadow": false,
  "quiet_seconds": 60,
  "max_wait_seconds": 600,
  "batch_messages": 20
}
```

`shadow` 只关闭自动上下文注入；管理与回忆工具仍开放，不能把它当作全功能不影响回复的影子模式。生产通过隔离的合成数据测评后正常启用。旧画像按需迁移，旧停记状态保留，历史关系不回填。

维护者可在服务器本地查看积压和错误：

```bash
docker exec shadow-desktop-1 /opt/weixin-venv/bin/python /bot/member_memory_admin.py
```

提供 `--group '<会话ID>' --member '<成员ID>'` 可查看该范围的关系数值与画像；加 `--evidence` 查看近期计算证据。这是服务器命令，不是给聊天模型的工具。不要把带私人内容的输出公开分享。

验证覆盖范围与实际测评结果见 `member-memory-evaluation.md`。长期自然度需要持续观察真实相处，不能用有限样例证明已经“像真人一样”。
