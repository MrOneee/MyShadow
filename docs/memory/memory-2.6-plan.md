## 分析与实现计划

源码在observe时将已确认助手回复截到800字符，任何后续检索都无法恢复后部细节。旧回归中的长篇已确认方案有明确例子。读取时又把用户问题与助手回答放入同一600字符窗口，容易只留下引入部分而丢失具体数量。这是通用信息保真问题，不能靠继续提示“认真回答”修复。

将已确认助手回复保存上限从800提高到4000字符，用户正文仍1000；资格/敏感筛查仍先作用于完整输入，不存未确认草稿，不扩大共享范围。提取批次继续受11000字符和成员数限制，单条也不应突破现有请求预算。写入变化必须从干净库重放全部52个历史，不复用旧提取结果。

对已保存的确认经历，在读取阶段按用户原话与助手原话区分角色，并在长正文中提供多个互补命中窗口，避免用户问题中的专名挤掉助手细节；原有存储内容与引用仍可追溯。同一来源的多个窗口不当作多次独立事件。窗口和总候选有界，最终仍6500字符/12条，模型只能选真实片段。旧库仅更新版本标记，不自动回填被截断或删除的原文。

验证长回复后部可检索、用户/助手角色不混淆、窗口预算、删除联动、跨会话不可见、调用中撤回，以及既有101项回归。冻结实现后运行完整160题；过线才独立重复和68题确认。记录新增提取调用、储存量与成本，不改模型或裁判。
