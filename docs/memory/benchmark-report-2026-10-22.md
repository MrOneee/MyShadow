# MyShadow 长期对话记忆评测报告

日期：2026-10-22，北京时间。状态：**本轮预定抽样评测已完成**。

**结论：在本轮离线配置下，当前记忆组件能提供少量有效个人信息，但不足以支撑一般的长期对话回忆。主要问题是自动上下文覆盖有限、回答模型很少主动检索，以及信息保存方式不适合完整事件和时间线。不能用本结果直接评价线上 DSH Agent 的整体能力。**

此次使用 LongMemEval 清洗版 28 题、LoCoMo 98 题，运行无记忆、当前记忆、标注证据三个条件，共 **378 份回答和评分**，无缺失、无 API 错误、无评分错误。原始历史全部输入，生产规则的截断和过滤照常执行。相关自动化测试 **51 项通过**，被测生产源码哈希在结束时与开始时一致。

## 1. 评测范围与可信边界

评测方案在正式推理前生成，见 [评测方案](benchmark-plan-2026-10-22.md)；模型、身份映射、下载来源及运行环境差异见 [执行说明](benchmark-execution-notes-2026-10-22.md)。

- 被测对象：工作区当前 `MemoryService` 的 observe、update_once、context、handler/recall。保留画像提取策略、敏感过滤、身份隔离、冲突处理、FTS 检索和读取限制。
- 运行：2026-10-22 **12:15:14–12:23:39**，约 **8 分 24 秒**，8 个独立样例线程。各样例内部顺序重放历史。
- 模型：提取、回答、裁判均为 **deepseek-flash**，temperature=0，thinking=disabled。原项目文档的 deepseek-v4-flash 名称不在接口模型列表中。所有正式响应的模型名称及用量保存在调用日志中。
- 本机没有 DSH，回答使用原生工具循环和生产 READ_POLICY；不覆盖微信入口、DSH、人格、短期历史、滚动摘要、search_history 或梗记忆。因此是**记忆组件及本次回答接入的测评**，不是线上端到端验收。
- LongMemEval 使用官方 cleaned/S 完整历史，按七层各抽4题。LoCoMo 覆盖全部10段对话，每段每类抽2题；一段缺少类别3，因此实际98题。种子20261022，清单在推理前固定。
- 原始英文未翻译；中文产品的提取规则仍生效。LoCoMo 两位人类映射独立成员，以两个已绑定的只读工具读取；没有伪造机器人共同经历。提供双方自动画像比生产默认相关成员入口更宽，但工具名称和提示接入也不同，不能视为生产同配置。
- LongMemEval 主站连接超时，数据从 hf-mirror 对应官方仓库路径取得。保存文件 SHA-256，未能从主站独立校验。LoCoMo 和评分源码来自作者 GitHub。

这是分层抽样诊断，不是官方全量榜单分数，也不是原始题型分布下的无偏总体估计。未加入完整历史、滚动摘要或普通 RAG 对照，故不能据此比较这几类方案。

## 2. 主要结果

LongMemEval 使用作者原始分类裁判提示，替换为 deepseek-flash 裁判；LoCoMo 使用作者分类 F1/拒答规则，另报告语义裁判。两种数据集的分数不能相加平均。

| 数据集与指标 | 无记忆 | 当前记忆 | 直接提供标注证据 |
|---|---:|---:|---:|
| LongMemEval 全部28题正确率 | 14.29%（4/28） | **25.00%（7/28）** | 85.71%（24/28） |
| LongMemEval 可回答24题正确率 | 0%（0/24） | **12.50%（3/24）** | 83.33%（20/24） |
| LongMemEval 不可回答4题正确拒答 | 4/4 | **4/4** | 4/4 |
| LoCoMo 可回答78题官方 F1 均值 | 0.64% | **3.27%** | 46.92% |
| LoCoMo 可回答78题语义正确率 | 0%（0/78） | **5.13%（4/78）** | 73.08%（57/78） |
| LoCoMo 对抗20题语义正确拒答 | 20/20 | **20/20** | 18/20 |
| LoCoMo 全部98题官方混合分 | 20.92% | **23.01%** | 54.69% |
| LoCoMo 全部98题语义正确率 | 20.41%（20/98） | **24.49%（24/98）** | 76.53%（75/98） |

LoCoMo 的“官方混合分”将类别1–4的 F1 与类别5固定拒答短语命中率合并，**不是统一 F1 或准确率**。标注证据条件的类别5短语命中为17/20，与语义裁判18/20不同。

当前记忆在 LongMemEval 的24道可回答题中有21题直接答“无可用信息”，LoCoMo 的78题中有69题这样拒答。故总分中很大部分来自拒答题，不能解读为已经能回忆四分之一的事实。

相对无记忆，LongMemEval 多答对3题，增加10.71个百分点；LoCoMo 多答对4题，增加4.08个百分点。4000次配对自助抽样的描述性95%区间分别为 **[0, 21.43]** 和 **[0, 8.33]** 个百分点；LoCoMo 按10段对话聚类。样本小且只运行一次，语义增益区间含0，不足以宣称稳定显著提升。它不涵盖模型随机性、数据构造偏差或不同裁判的偏差。

## 4. 可追溯的问题与复核

对14个代表性结果进行了逐项文本复核，记录在 [复核记录](../../benchmarks/memory-eval-2026-10-22/manual-review.json)。**复核由本次代理完成，不是独立人工盲评；不覆盖全部题目，也未覆盖原始裁判分。**

### 4.1 回忆工具调用不足，自动画像不能替代问题相关检索

28道 LongMemEval 记忆题总共调用回忆工具4次；98道 LoCoMo 题共16次。全部工具调用无错误。另行连接诊断验证，同一模型在明确要求下能正常调用 recall_memory。

例如 `0977f2af` 问“买空气炸锅之前购入的厨房设备是什么”，答案为 Instant Pot；模型只看自动注入画像就拒答，没有主动检索。`4b24c848` 问 H&M 上衣累计数量，也未检索。

这首先是**本轮模型、提示与原生工具循环组合**的行为问题，不能直接断言生产 DSH 同样不检索。自动上下文主要挑选少量近期画像，缺少按当前问题召回的保障。

### 4.2 事件正文截断丢失关键信息

`6071bd76` 的两段原始用户消息分别提到每汤匙咖啡用6盎司和5盎司水，数值都位于正文180字符之后。生产经历由用户正文前180字符和助手正文前180字符拼成，读取还会限制为300字符。手工只读检索能找到有关法压壶的经历，却不能保证返回两个关键比例。

当前记忆拒答，标注证据条件正确回答“水量变少”。这是具体的保存/读取截断损失，扩大模型上下文无法自动补回已经丢失的文字。

### 4.3 累计数值被视为矛盾，影响可见性

`4b24c848` 标准答案为5件。独立只读诊断查到“已买3件”和“已买5件”两条画像，都标为 needs_confirmation；自动上下文没有展示它们。此题既存在未主动检索，也存在更新语义未能区分“新增累计”与“相互矛盾”的问题。

该诊断未重新生成正式答案，也没有把其结果写回记忆。

### 4.4 普通成员对话不进入经历库，画像无法覆盖全量叙事

LoCoMo 5,882条普通发言提取了1,360条事实记录，但共同经历为0：生产实现只给已确认机器人 exchange/activity 建立经历，测试没有把两位人类冒充机器人。这是当前产品建模范围与基准之间的真实差异。

例如 `0:60` 问 Melanie 会哪些乐器，模型只答单簧管，遗漏小提琴；完整答案要求两者。动态事件、第三人关系及多条事实整合普遍比单条偏好更难覆盖。

### 4.5 隐私规则和英文基准存在目标差异

例如 `0:50` 要求推断政治倾向，而项目策略明确限制政治等敏感信息。此类失分不能直接当作应解除隐私限制的缺陷。本报告保留全部预选题的原始成绩，没有事后挑掉低分题；也没有把全部错误统一归因于隐私过滤。

生产政策并非完美语义分类器，本次也未专门评估其敏感信息过滤准确率。

### 4.6 给正确证据仍有推理错误，裁判也有争议

`b29f3365` 中“已经学吉他6周、2周前买音箱”应推出买音箱时学了4周；标注证据条件仍答6周。LongMemEval 时间题在证据条件下仅1/4正确，说明部分差距属于阅读/推理能力。

偏好题 `195a1a1b` 被裁判判对，因为给出9:30前放松的个性化建议，但建议包含冥想应用，可能违背参考标准中的避免手机偏好。保留官方提示的原始裁判结果并标注争议；若严格将此题判错，LongMemEval 总正确率从25.00%降至21.43%，可回答题从12.50%降至8.33%。这不是另一次正式评分。

LoCoMo `9:66` 的参考答案是“No”，无记忆条件答“No information available”，竟获得0.5 F1，语义裁判则正确判错。这说明词重合分不能单独代表记忆成功。

## 5. 来源覆盖与资源

从返回文本反查事实/经历来源，LongMemEval 28题中仅9题返回至少一个标注证据会话的来源，3题覆盖全部标注会话；LoCoMo 98题中对应为11题和8题。

这些数值包含不可回答题附带的关联证据。相同文本可能对应多个来源，且命中会话不代表关键答案未被截断，因此只是**偏乐观的来源诊断，不是官方 Recall@K**。LongMemEval 全部28题都能在存储中找到标注会话的派生记录，也不能据此声称答案已完整保存。

## 6. 改进优先级

本次只评测，未修改生产记忆行为。

1. **先验证生产 DSH 的回忆行为。** 在同一固定样本上对照原生循环与真实 DSH；对涉及过去事实的问题记录是否检索。若同样漏查，再考虑确定性触发一次问题相关检索。不要直接把本轮接入差异归因于全部 Agent。
2. **保留可回溯证据，减少截断损失。** 在现有权限和隐私范围内，给检索结果保留安全的来源读取入口，或围绕相关内容返回片段；不要只保留所有消息的开头。
3. **区分画像与事件。** 若产品目标确实包含长期事件问答，再设计允许保存的事件/时间线；不把普通聊天全量转成“机器人共同经历”，不关闭既有敏感过滤。
4. **改进累计/更新语义。** 对3件到5件、旧比例到新比例等更新建立可追溯状态；保留不确定性，但避免把明确的时间演变一概当矛盾。
5. **改进后扩大验证。** 保留本轮题目作回归，另选未用于调试的样本，再做全量 LongMemEval/LoCoMo，并补中文、生产 DSH、删除与跨成员隔离评测。本轮数据不证明中文线上质量、删除能力或长期自然度。
