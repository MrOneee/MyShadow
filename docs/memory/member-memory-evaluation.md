# 成员记忆验收记录

日期：2026-09-10。模型：`deepseek-v4-flash`。测试使用合成成员与独立临时存储，不向微信发送测试消息。

## 自动化测试

完整 Python 回归 **407 项通过**；最终 **45 项记忆与轮询定向回归通过**，补充观察过期标记、PTC 空参数/报错契约、旧画像只迁移到首个人设范围，以及入队失败时游标不推进的校验。两组测试存在重叠，不相加计算独立用例数量。新增记忆单元及集成测试覆盖：

- 账号、人设、群与私聊隔离；同名成员不能串档案。
- 多值画像、称呼纠正、旧版本检索、部分删除、全部删除、停记和恢复。
- 在途提取被删除版本拦截；工具缓存同步失效；旧事件不能恢复已忘记的资料。
- 原话与真实成员证据检查、重复消息防刷分、每日上限、单次批评不扣分。
- 100 条多天合成互动轨迹，每条 15 个互动窗口，验证累计、阶段与日上限。
- 关系账本重建、同窗口后续积极证据、队列重启/重放、写入失败保留 outbox。
- 只有 confirmed 回复及活动交互产生经历；发送失败/不确定/预览不计入。
- 参与决策接入、读取预算、旧画像迁移及保留期。

100 条轨迹是程序规则测试，不是 100 条真人对话盲评。

## 真实模型提取与回复

10 条中文输入、两次实际提取调用，14 项断言全部通过：兴趣保留、称呼替换、边界保留、第三人转述不归入本人、引用不归入本人、临时情绪不固化、纠错/互怼不扣分、要求加分不生效、范围隔离、不暴露分数、删除有效。

积极合作样例使好感从 50 变为 51。模型提取的是关系事件，数值由程序计算。

初次测评发现两类问题：一次性资料归属澄清被泛化为边界；没有任何记忆时模型编造爱好。已加强规则并复测。昵称检查也曾误把新值中“**不再**使用旧称呼”判断为纠正失败，已将断言改为检查唯一当前称呼记录与新称呼，而非禁止旧名字的任何字面出现。

同一问题“你还记得我喜欢干什么不？今天终于下班了”的最终对比：

| 输入条件 | 实际回复摘要 |
|---|---|
| 无记忆 | 说明手头没有相关记录，未编造爱好 |
| 画像 | “记得。徒步、摄影。下班了就歇会儿。” |
| 画像 + 关系 | “喜欢徒步和摄影。下班了，歇会儿吧。” |

这组结果证明画像提供了正确事实，但**没有证明加入关系状态后，回复自然度显著优于仅有画像**。两者在这个短问题上很接近。需要更多真实相处样例和人工盲评判断长期收益，不能用一次模型自评分代替。

完整合成数据结果在 `member-memory-live-evaluation.json`。最终一轮两次提取加三次回复共 4,879 tokens；不是实际生产每百轮成本估算。

## 资源与限制

独立进程实测，记忆测试期间峰值 RSS 增量约 2.1 MiB，SQLite 文件 144 KiB。这不是整个机器人启用前后的常驻内存对比。

200 次上下文读取的中位数约 3.6ms；该轮 p95 为 47.5ms，超过方案中的 30ms 目标。前面两轮 p95 为 4.1ms、6.3ms，服务器并发负载明显影响结果。随后消除了已存在成员读取时不必要的写事务，生产复核另记录，不宣称稳定达到 30ms。

上线后的独立合成读取复核：p95 3.69ms、中位数 1.94ms；服务主进程 RSS 约 51.8 MiB（整个主进程，并非本功能增量）。当时记忆队列无积压、无任务错误。

目前使用中文 FTS，没有语义向量召回；隐喻式查询和关键词完全不同的经历召回需继续评测。陌生人阶段不会因单次夸赞迅速变成熟人。对好感的自然语言分类仍有模型误差，证据检查、日上限和用户纠正机制用于限制误差影响。

## DSH 与部署复核

发布过程使用真实 DSH、独立临时存储测试普通模式的记住/回忆/忘记，以及 PTC 模式的只读回忆。结果保存在 `member-memory-harness-evaluation.json`。生产健康与积压复核保存在 `member-memory-deployment.json`。

四个实际工具链样例全部通过。普通回忆回复“记着一条：你喜欢篮球”，PTC 回忆正确返回同一偏好；删除后返回停记状态。没有把原始好感分或任务内部编号暴露给聊天输出。

实际联调发现并修复：预发布目录缺少既有 QuickJS 依赖链接；回忆实现允许空查询，但工具声明要求关键词，且输出契约没有接受宿主的校验错误详情。现在省略 query 可查看概览，PTC 也能读取具体校验反馈。短句“忘记我”在机器人入口走确定性控制，不依赖模型是否再次确认；工具链测试使用完整明确的删除请求。
