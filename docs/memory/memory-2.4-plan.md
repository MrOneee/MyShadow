# 2.4.0目标迭代第二轮方案

日期：2026-10-22。第一轮2.3结果为LME24/36、LoCoMo36/92，均未达标。已发现明确的非敏感原话虽已保存，却因类别词、具体名称和跨语言词面不重叠漏检。

本轮只改读取，不改2.3提取规则。SQLite backup复制52个2.3库，升级副本后运行固定160题memory条件；原2.3库保持不变。数据、题目、模型、评分不变，新增34题继续封存。

## 实现

给MemoryService绑定可选只读模型工厂，生产Bot及评测都绑定同一生产选择入口。先按成员/会话与替代记录可见性取得候选，再向模型提供有界目录（最多240条、约48000字符），包括摘要、截取原话、类型、来源时间。目录由现有词面命中及同来源的事件证据组成，超限时保留词面相关项并分散取时间样本。模型只输出记录序号，宿主校验序号并返回实际存储的原话，不能让模型编造引用或答案。

最终回答记忆预算仍6500字符、最多12条；原有至多两次主动回忆不变。每次语义选择新增一次模型调用，LoCoMo两个成员分别选择；这是显著增加读取计算预算，不能宣称同成本改进。提取规则及旧记忆内容不变。

模型调用在数据库事务外进行。调用前后核对成员revision和停记/控制version，期间发生删除、纠正或停记则丢弃旧候选，防止返回已经撤回的资料；自动上下文相应重新读取。模型失败或输出非法序号时使用有界词面回退，并记录detail/调用错误，不隐藏失败。

仍不开放未筛选原始事件库，不共享原话到其他会话，不改变敏感过滤。目录是低信任资料，不能触发工具、修改库或成为指令。记录序号仅用于内部选择，不暴露给最终用户。未绑定模型的单元测试/离线调用保留确定性词面路径。

验证语义选择绑定、跨语言已存记录选择、伪造序号、目录预算、调用期间删除/停记、来源隔离、迁移幂等以及现有回归。冻结后只运行一次完整第二轮，完成再分析；所有未达标轮次保留，达标后仍需独立重复评分及封存34题验证。
