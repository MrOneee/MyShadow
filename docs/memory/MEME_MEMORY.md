# 梗记忆设计与调参

## 已确认的行为

影子在收到明确要求时记梗；普通发言中的重复概念先进入候选，默认同一会话七天内至少三条不同消息，再由模型决策是否像网络梗，经过 web_search 核验后自动保存。没有证据不猜含义，不为入库单独发群消息。用户直接解释的群内梗可以不搜索。

公共网络梗全局可见；自创梗、私人梗仅当前会话可见。公共结论只保存公开搜索证据，不把聊天原文变成全局知识。所有成员可管理本会话梗；全局修改、删除及显式创建只允许设置中的主账号。自动公开核验可建立公共词条，但不能覆盖已有全局定义。

## 实现

新增 `myshadow/meme_memory.py`，用独立 SQLite 保存消息候选、含义、来源、状态和管理操作。独立于成员画像，不修改好感度。采集只处理启用后的新文本，消息键去重；候选队列有时间和数量上限。后台串行整理，不阻塞数据库轮询。候选抽取后必须在至少三条不同原文中找到概念，模型不能凭空报告次数。

显式请求通过绑定当前发送者和会话的 `manage_meme` 工具提交；宿主验证当前请求确有管理意图、目标范围和管理员身份。支持 remember、correct、forget、list。缺少解释时先查询公开资料或追问，不把模型既有知识冒充搜索结果。自动核验需要成功搜索、来源链接和与候选一致的结构化结论。

回复上下文按当前话题匹配梗，相关含义始终可用于理解；自然使用有概率、冷却和过时衰减，不增加主动发送入口。梗资料作为不可信引用注入，不能改变工具权限和人设规则。注入有字符上限并参与原有上下文预算。既有主动接话路径也只读取本会话与公共资料。

使用小型类和直接函数，不引入设计模式：直接实现更简单。

## 设置文件

根目录 `meme-settings.json` 是运行设置，每轮读取，修改后下一轮生效；非法配置保留最近一次有效设置并记录错误。主账号 ID 放 `admin_ids`，部署时从微信好友库唯一核实 Mr.One 后填写，不能用模型提供的昵称授权。

明确记录示例：“影，记住这个梗：摸鱼的意思是偷偷闲下来休息”。保存私人含义时取用户解释原文。若只说“记住摸鱼这个梗”，宿主会先联网核验，证据明确才加入公共词典；无证据时追问，不猜。普通成员不能改写既有公共含义，但可以记录当前会话的特殊解释。自动发现和搜索的关键词脱敏依赖模型决策，不是完美的语义隐私过滤。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| enabled | true | 总开关，关闭后不采集、整理、读取或管理 |
| auto_discovery | true | 普通消息自动发现；关闭仍允许明确请求 |
| window_days | 7 | 重复概念统计窗口，1–30 天 |
| min_mentions | 3 | 不同消息最少次数，2–20 |
| decision_interval_seconds | 300 | 同一会话两次候选整理最短间隔，30–86400 秒 |
| max_messages_per_scope | 200 | 每会话最多候选原文，20–1000 |
| max_searches_per_day | 12 | 所有会话合计自动搜索次数，0–100 |
| max_decision_chars | 12000 | 候选决策输入字符上限，2000–30000；按新到旧取每条最多300字，可能漏掉窗口内较早的概念 |
| use_probability | 0.12 | 相关梗可自然使用的概率，0–1；理解不受影响 |
| use_cooldown_seconds | 1800 | 同一会话允许主动用梗的最短间隔，0–604800 秒 |
| stale_days | 90 | 过时阈值，7–3650 天；保留理解，使用概率降为四分之一 |
| max_context_chars | 1200 | 单次注入长度，300–3000 字符 |
| admin_ids | [] | 全局梗管理员的真实微信 ID |

希望更容易发现：降低 min_mentions 或 decision_interval_seconds，但会增加模型调用。希望更克制：降低 use_probability、增加 use_cooldown_seconds。使用概率为零仍会理解已存梗。公开热梗一经核验长期保留；旧梗自然降频。忘记采用逻辑删除和版本屏障，防止后台在途任务重新写回；原始微信聊天不受影响。

## 部署与验收

先本地测试候选去重、窗口、搜索失败、范围隔离、真实管理员权限、删除竞态、设置重载及上下文预算，再在服务器隔离测试目录验证 Linux 主流程。部署前备份变更文件，原子替换，不覆盖登录态或聊天数据库。

本次用户要求部署但不重启机器人。Python 已加载的业务模块不会因为文件替换而自动生效：新功能在下一次正常启动后加载；不得声称部署即已启用，也不通过动态注入或另起发送进程绕过。完成汇报通过现有可信发送链路给唯一核实的 Mr.One，注明部署、验证与待正常重启生效状态。

搜索复用现有 Harness 的原生 `web_search`，要求宿主收到实际成功的搜索事件；不接受仅有模型解释的结果。显式记梗先在主回复循环之前预取公开证据，工具回调仅核验和提交，不嵌套启动 Harness。搜索关闭或接口失败时，显式请求可改由用户解释；自动候选暂不入库。搜索日志在 `harness-data/memes/`，同样属于私有运行数据。
