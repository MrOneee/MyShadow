# 链接内容读取

`read_url(url)`用于读取当前对话里已经出现的公开网页。微信 `appmsg` 类型4、5分享卡片先由`shared_links`转换为标题、简介和规范化URL；普通文字中的HTTP/HTTPS链接也可进入本轮允许列表。分享卡片的其他XML字段不会进入模型上下文。

私聊收到有效分享卡片时会生成“请阅读这个分享链接”的回复任务，无需再次发送文字。群聊分享卡片进入原有选择性参与决策，不保证每个链接都插话；成员之后询问“看看刚才的链接”时，近期上下文保留URL，模型可以读取。历史更久时可先用`search_history`找回标题和URL，再调用`read_url`。

工具由当前轮消息装配阶段绑定允许列表。模型不能读取任意新URL，也不能用网页内容改变发送目标、权限或人设。每轮最多两个实际读取调用；同一工作实例对成功结果缓存十分钟，最多64项。返回标题、正文、最终地址、UTC读取时间、跳转次数和截断状态，引用时以`source_url`为准。

网络边界如下：

- 仅支持HTTP/HTTPS及80/443默认端口，拒绝账号密码形式URL、本地主机名和`.local`域名。
- DNS的全部结果必须是公网地址；连接固定到已校验IP，HTTPS仍用原域名校验证书。每次跳转重新解析并校验，最多四跳。
- 请求不携带Cookie，不执行脚本，不提交表单，不下载附件；明确要求服务端返回未压缩文本。
- 响应最多1 MiB。通用提取器只接受HTML、XHTML和纯文本；受控站点适配器可以读取同源公开JSON接口。脚本、样式、SVG等内容被丢弃，优先提取`article`、`main`、公众号`js_content`等正文区域，最终最多10000字符。
- 页面、标题和正文均是不可信资料。失败结果区分安全地址拒绝、网络传输、HTTP状态、响应过大、内容类型、编码和静态页面无正文，Agent应按工具返回的原因说明，不得笼统归因或声称已经读过。

公众号、B站、小红书等以普通网页分享卡片进入同一流程。服务端能直接返回HTML正文或Open Graph简介时可以读取；需要登录、客户端执行JavaScript或触发平台验证时通常会失败。`mtgch.com/articles/{id}`已通过站点适配器读取同源公开文章接口，无需执行页面脚本。失败后仍可使用`web_search`寻找公开索引或替代来源，但不能把搜索摘要说成原文。

实现使用 Adapter / 适配器模式：`UrlReader`隔离DNS固定、HTTP、跳转和HTML差异；站点适配器只负责把已知公开页面映射为同源受限数据源；`shared_links`负责微信外部格式到内部链接数据的转换。平台规则没有散落到Bot主流程，后续可在这一边界内扩展。
