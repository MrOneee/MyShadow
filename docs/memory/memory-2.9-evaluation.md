## 依据与实现

2.8旧回归12题候选审计中，目录60–179条，未被240条上限截断。关键原话已返回、答案却漏列或拒答的案例存在；另有图片信息、未保留的对话上下文和隐私排除，不能全部归因于存储或目录大小。本轮不查看2.8新题问答来调参，依据见[候选审计](../../benchmarks/memory-eval-2.8-2026-10-23/candidate-audit.json)。

读取提示补充通用的内部核对过程：看完全部相关记录再列举，利用有根据的人物/对象/话题/时间关系连接陈述，实际计算跨事件时间差。主体事实已知而个别修饰条件不清楚时，仅对未知部分保留不确定性，不能整题误拒答；仍禁止用问题预设、普通常识补出个人事实或推断敏感属性。

语义结果中，同一来源、角色、说出时间且原话包含的来源片段和经历窗口只保留更完整的宿主记录，不生成新摘要。不同来源、角色、时间和画像状态不合并。240条/160000字符目录、2400 token选择输出、最终最多16条/9000字符以及模型调用次数均不变；新增提示仍会增加输入token，不能宣称成本完全不变。

只读复用2.8的52个SQLite副本，内容来自2.6完整写入；不重提取、不复制旧回答/评分。deepseek-flash、temperature=0、thinking关闭、题集和裁判保持冻结。先定[方案](memory-2.9-plan.md)，再封存新68题（种子20261029，排除此前432题），之后实现并冻结源文件及评测脚本。

## 新题确认与判断

固定160题两次都需LME至少26/36、LoCoMo至少56/92；随后本轮新68题需LME至少17/24、LoCoMo至少20/32。本轮新题实际15/24（62.50%）、17/32（53.13%），两项未达标，completion-audit.json明确false；没有重新抽题择优或修改评分。

68份回答/评分完整、API/评分错误0；拒答LME4/4、LoCoMo7/8；LoCoMo可回答官方F1为23.94%。2313次请求、10,931,755 token，其中新历史写入8,683,073 token，选择1,934,839、回答303,547、评分10,296 token。自动选择104次正常、4次词面回退，无主动回忆。完整资料见[confirmation](../../benchmarks/memory-eval-2.9-2026-10-23/confirmation/)。

这是与2.8不同的封存新题，不能把分差全归因于版本。下一轮继续依据旧160题和已完成的诊断，尝试在保留原文上下文的同时，突出逐字可核验的名称、动作、数值等候选值；不查看本轮新题问答定制规则。

固定题集已用于多轮开发，必须同时看新题，不能代表全量基准。新LoCoMo仍来自原10段对话池，不是新对话泛化。当前重放只使用文字，不包含图片理解；一次性离线重放也不代表上线后跨越90天来源/180天经历保留期的行为。来源重建是乐观诊断，不是官方Recall@K。回答与语义裁判使用同一模型，存在生成及评分波动；样本达标不等于总体正确率置信下界达标。
