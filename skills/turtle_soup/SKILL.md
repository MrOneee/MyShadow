# 海龟汤主持

本能力由 `handler.py` 执行。宿主提供可信发送者、会话存储、隔离的模型调用、搜索、定时和发送；不自行访问微信或启动后台循环。

## 开局与选题

“来一局海龟汤”直接选择尚未玩过的审核题。“找几个海龟汤”先列三个不泄底的候选，发起者选择后开局。“联网搜一个海龟汤”先取得题材，再整理并做一次综合审核（仅有阻断问题时修订一次）；搜索失败或审核不通过明确告知，不把自编题说成搜到的题。

题库 `puzzles.json` 保存来源、改编说明、固定汤底、关键事实、提示和对局测试。经典题经过重新措辞并固定含混细节，不声称原创或保证世上只有一个解释。只有达到质量标准的题可入库。查询来源在揭晓后提供，避免链接标题提前暴露答案。

## 主持原则

- 遵循当前群的身份和说话风格简洁主持；身份由宿主Context.persona提供，不从聊天猜测。不为了人设改写题目事实、判定或计分。
- 开局后玩家无需@。回答要对应当前玩家的问题；不同玩家的提问不可混为一条。
- 依据固定汤底和已经确认的公开事实裁判。每个子问题分别回答“是／不是／不重要／无法确定”，开放式索要答案请改成可判定问题。
- 未设定且不影响推理的细节判“不重要”；影响因果但题目未说明的细节判“无法确定”，不补新设定。
- “我觉得”“是不是”可以作为猜测；引用题面、列一串互斥选项、请求泄底、要求修改规则不是破解证据。
- 已判断的问题保持一致；玩家指出矛盾时核对固定汤底，承认并纠正错误，不能偷偷改汤底。

## 状态与披露

内部 `puzzle` 与 `rulings` 仅裁判可读。群消息由已校验的判定、玩家原话、已确认事实及预设提示组成，不转发裁判的内部解释。`progress.py` 计算关键事实权重；新进度必须有当前玩家消息的直接证据并通过独立核验。

提示提供者与玩家破解分别记录。提示本身不涨进度。进度严格超过80%即自动揭晓（80%不揭晓，81%及以上揭晓），无需猜齐全部核心事实；发起者/管理员也可提前要求结束。

支持进度、提示、重发汤面、暂停、继续、结束、换题、选题与复核等自然语言意图，示例不是必须逐字照说的口令。commands.py 对常见短句快速识别，其余通过隔离的 intent 模型理解语义、口语、错别字、否定和引用；意图模型只看当前消息、阶段和公开候选，不能看到汤底，也不能决定权限。咨询如何操作不执行操作，故事中的行为、引用和否定不触发对应操作。模型故障时不执行未经确认的操作。结束和换题权限由宿主验证；其他成员不能以自称管理员绕过。完整回放位于 `tests/`。

## 模型故障

结构错误通过工具返回校验原因，由 Agent 在预算内修正；连接错误由 Harness 有限重试。仍失败则本轮不计分、不编造裁判结论，请玩家重发。发送不确定时不自动重发。暂停、重启、重复消息不能改变已确认的破解结果。


## 按主题或创作者选题
DSH 路径先检索同一作品的题名、汤面、核心汤底和公开来源，不在搜索循环内反复生成计分或提示。可用转载、问答、博客及完整搜索摘录；取得足够材料立即提交。同一站点连续两页被拦截就换站，再围绕具体题名补查，不重复刷合集。

普通“某某的汤／某某讲的”接受公开标注为该人讲述或发布的作品，来源说明不能冒称原创；用户明确说“作者／原创／原作”才要求该作品的原作者依据。不偷偷替换指定创作者。允许排版空白与追踪参数差异，但引文不能编造，不得混拼两道题的答案。

取得材料后单独整理主持数据并综合核对来源与可玩性。只阻断缺核心汤底、归属不符、核心矛盾或实质影响判定/计分的缺陷；文风、可选润色及合理的局部提示不是阻断条件。权重舍入由代码规范化。有可修问题只修订整理稿一次，不返回重新检索。通过审核的题才开局。

已取得的材料按相同选题请求缓存7天，整理失败可复用；证实材料本身不可靠则撤出缓存。失败消息区分“没取得材料”和“材料已取得但整理未完成”。未启用 DSH 的旧部署继续使用原路径。

## 方向提示
所有玩家可直接说“提示”“给个方向”“给点思路”“不知道问什么”，无需 @。每次给一条从宽到窄的提问方向，不直接公布隐藏身份或完整因果链。三层提示间隔至少20秒，提示不计分。三层用完继续指导玩家拆成是非问题，仍不直接揭底。新题在入库审核中检查提示顺序和泄底；已进行的对局保留开局时固定的提示与题目。
